# D1 · 工程与仓库初始化

**总预计 60–90 分钟。** 目标只有一个：**从今天起，你的所有工作都有版本历史。**

## A. 开工前（约 5 分钟）

**A1｜关掉 Unity** — 判据：任务栏没有 Unity 图标。（Unity 开着会锁工程文件，Git 操作会报错）

**A2｜确认 Git 装了** — Win 键 → 输入 `cmd` → 回车 → 输入 `git --version` → 回车
- ✅ 显示 `git version 2.x.x` → 进 A3
- ❌ 提示"不是内部或外部命令" → 打开 https://git-scm.com/download/win 下载 **64-bit Git for Windows Setup**，安装时**一路默认下一步，但绝不要取消 Git Credential Manager**；装完**关掉 cmd 重开**再验一次

**A3｜打开工程** — Unity Hub → Projects → `My project`（路径 `D:\aDesktop\unity project\My project`）→ 点开。首次导入可能要几分钟，等它跑完
- 判据：Project 窗口能看到 `Assets` 下有 `StarterAssets` / `Scenes` / `Settings`
- 如果 Hub 提示安装 Unity Version Control / 升级包：**全部忽略、点取消**。我们用 Git，不用 Unity 自带的版本控制

## B. 建自己的目录（约 5 分钟，全部在 Unity 的 Project 窗口里操作）

> 为什么必须在 Unity 里建：在资源管理器里建文件夹不会生成 `.meta` 文件，Unity 的引用会乱。

**B1｜建根目录** — Project 窗口点 `Assets` → 右键 → Create → Folder → 命名 `_Combat`
（下划线让它排在列表最上面）

**B2｜建二级** — 选中 `_Combat` → 右键 → Create → Folder → 建 `Scripts`
**B3｜建二级** — 同法再建 `Data`、`Scenes`
**B4｜建三级** — 选中 `Scripts` → 建 `Core`、`Player`、`Combat`、`UI`

判据：`Assets/_Combat/` 下面有 `Scripts/`（内含 Core、Player、Combat、UI）、`Data/`、`Scenes/`

## C. 建自己的场景（约 3 分钟）

**C1｜新建场景** — 菜单 File → New Scene → 在模板列表里选 **Basic (URP)** → Create
**C2｜保存** — File → Save As… → 进入 `_Combat/Scenes` → 文件名填 `Combat` → Save
（文件名只用英文、小写、无空格）
**C3｜清标签页** — 右键旧的 `SampleScene` 标签 → Close Tab，只留 `Combat`

判据：Hierarchy 里只有 `Main Camera` 和 `Directional Light`；Project 里 `Assets/_Combat/Scenes/Combat.unity` 存在

## D. Git 初始化（约 15 分钟）

> ⚠️ **必须在工程根目录 init，不是在 Assets 里。** 仓库要包含 `Assets`、`Packages`、`ProjectSettings` 三样。

**D1-1｜进对目录** — 在 cmd 里执行：
```
cd /d "D:\aDesktop\unity project\My project"
```
判据：执行 `dir` 能看到 `Assets`、`Packages`、`ProjectSettings` 三个文件夹

**D1-2｜初始化** — `git init`

**D1-4｜暂存 + 检查污染** — 依次执行：
```
git add .
git status --short | findstr Library
```
判据：**第二条命令必须没有任何输出。** 如果输出了 `Library/...` 的行，说明 .gitignore 没生效（回去看 D1-3 的记事本陷阱），先执行 `git rm -r --cached Library` 再重来
- 这一步是在防最经典的初学者事故：把几个 GB 的 Library 目录提交进去

**D1-5｜第一次提交** —
```
git commit -m "chore: init Unity project, add combat prototype folder layout"
```
判据：输出里有 `files changed` 的数字（应该在几百个量级）

**D1-6｜确认** — `git log --oneline`
判据：看到 1 条 commit

## E. 推到 GitHub（约 20 分钟）

**E1｜账号** — 打开 github.com 登录/注册
- ⚠️ **如果 github.com 打不开或一直超时：直接用 Gitee（gitee.com），后面所有步骤一模一样，国内招聘方同样认。不要在这一步耗超过 10 分钟。**

**E2｜建空仓库** — 右上角 `+` → New repository
- Repository name：`combat-proto`
- **不要勾 Add a README file**（会和本地冲突）
- 可见性选 **Public**（招聘方要能点开看）
- → Create repository

**E3｜连上远端** — 在页面上复制 HTTPS 地址（形如 `https://github.com/你的用户名/combat-proto.git`），回到 cmd 依次执行：
```
git remote add origin 你复制的地址
git branch -M main
git push -u origin main
```

**E4｜授权** — 首次 push 会弹出浏览器窗口要求登录 → 点授权（这是 Git Credential Manager，装 Git 时没取消它才会有）
判据：命令行出现 `main -> main`

**E5｜远端检查** — 刷新 GitHub 仓库页面
判据：能看到 `Assets`、`Packages`、`ProjectSettings` 三个文件夹，**并且没有 `Library`**

# D1 卡点速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| `git` 不是内部或外部命令 | 没装 Git / 装完没重开 cmd | 装 Git for Windows，**关掉 cmd 重开** |
| `git status` 里出现 `Library/` | .gitignore 没生效 | 文件名被存成了 `.gitignore.txt`。重命名，或 `git rm -r --cached Library` 后重来 |
| 提交时提示 `please tell me who you are` | 没配身份 | `git config --global user.name "你的名字"` + `git config --global user.email "你的邮箱"` |
| push 一直超时 / connection reset | 国内网络 | 换 Gitee；**别耗超过 10 分钟** |
| Unity 里 Play 之后按键没反应（D2 会用到） | Active Input Handling 设成了旧输入 | Project Settings → Player → Other Settings → Active Input Handling 改成 `Input System Package (New)` 或 `Both`，重启编辑器 |
| Unity 一直转圈编译 | 首次导入正常 | 等它跑完，别中途关 |
| 路径里有空格（`unity project`、`My project`） | 正常现象 | Unity 和 Git 都支持。以后如果遇到莫名的构建/CI 报错，第一个怀疑对象就是它 |

# D2–D7 · 半天粒度

> 只拆到半天，不往下拆。原因：D2 之后的步骤取决于 D1 的真实结果（目录结构顺不顺手、输入有没有坑），提前拆到分钟级是浪费，也是拖延的另一种形式。**D3 开始时再拆 D3。**

## D2-AM｜移动最小闭环
**做什么**：Hierarchy 建 3D Object → Plane，改名 `Ground`（Scale 设 5,1,5）；建 3D Object → Capsule，改名 `Player`，加 `CharacterController` 组件。用工程自带的 `Assets/InputSystem_Actions.inputactions`（已有 Move/Look/Attack）。写 `_Combat/Scripts/Player/PlayerMotor.cs`：读 Move 输入 → 相机相对移动 + 重力 + 落地判定。
**判据**：Play 后 WASD 能动、会掉到地面、不穿地。
**台账**：≥1 条。

## D2-PM｜相机与转向
**做什么**：写 `CameraRig.cs`：第三人称跟随（位置平滑插值）+ 鼠标控制视角；角色朝移动方向转（`Quaternion.RotateTowards`）。
**判据**：能绕圈跑，相机不抖；鼠标能转视角；角色朝向跟移动方向一致。
**台账**：平滑系数 0.05 / 0.15 的体感对比 → 选一个，写结论。

## D3-AM｜状态机本体（纯 C#，先不碰 Unity）
**做什么**：`_Combat/Scripts/Core/` 下写 `IState { void Enter(); void Tick(float dt); void Exit(); }` 和 `StateMachine` 类（`ChangeState` 保证 Exit 先于 Enter、防重入、可读当前状态名）。
**判据**：临时写两个空状态打 `Debug.Log`，Console 输出顺序必须是 `Enter A → Exit A → Enter B`；连续切换同一状态不重复触发 Enter。
**加分**：用工程已有的 Test Framework 写一个 EditMode 测试。会写测试的游戏客户端在面试里很加分。

## D3-PM｜接上玩家
**做什么**：写 5 个状态类 Idle / Move / Attack / Hit / Die，Attack 和 Hit **先只打日志**，不写逻辑。
**判据**：WASD 时进 Move、松开进 Idle；按键能强制切到 Hit，Hit 结束能回 Idle。

## D4-AM｜三层分离
**做什么**：拆成 `PlayerInputReader`（只读输入）/ `PlayerStateMachine`（只决定状态）/ `PlayerView`（只做表现，先用缩放 + 变色占位）。
**判据**：**把 `PlayerView` 组件整个删掉，状态机照样正确运行。** 这条能证明解耦，也是面试可讲的设计决策。

## D4-PM｜打断规则
**做什么**：定义可打断关系：Hit 可打断 Attack 和 Move；Attack 不可打断 Hit。
**判据**：攻击中被打 → 立刻进 Hit；Hit 期间按攻击 → 无效，且 Console 有日志说明被拒绝。
**台账**：≥1 条。

## D5-AM｜表现层挂钩
**做什么**：换上 StarterAssets 的 `PlayerArmature` 预制体，接 `StarterAssetsThirdPerson.controller`：Idle→待机、Move→走/跑、跳跃动作。**Attack 没有现成动画** → 先用占位（前冲位移 + 变色），或去 Mixamo 下一个挥砍动作（免费、商用许可）。
**判据**：Play 后动画与状态同步，不出现"状态切了动画没切"。
**台账**：≥1 条（记录你为什么选占位或选了哪个动画）。

## D5-PM｜调试面板
**做什么**：屏幕角上显示当前状态、当前速度、是否在地面。
**判据**：运行时数字随操作实时变化。
**别省这一步** —— 这是后面 W2/W3 所有迭代的观测手段，看不见结果就没法迭代。

## D6-AM｜两张图
**做什么**：状态机结构图 + 类关系图（draw.io 或手绘拍照）。
**判据**：能在 30 秒内向一个不懂的人讲清"输入 → 状态 → 表现"三条线。

## D6-PM｜台账与 README
**做什么**：整理本周 DEVLOG；README 里勾掉 W1。
**判据**：DEVLOG ≥3 条完整记录，其中 **≥1 条是推翻自己**；README 中 W1 已勾选。

## D7｜缓冲 / 补债 / 提前量
**规则**：D1–D6 全绿 → 提前做 W2-D1（技能 ScriptableObject 结构草图）；有没绿的 → 只补最卡的那一项。
**判据**：本周 `git log --oneline` ≥3 条有意义 commit。
