# 求职作战计划 · Unity 客户端 / 战斗程序

> 起点：已毕业、正在找工作、无实习无竞赛、毕设逻辑由 AI 完成、接受先中厂后大厂
> 目标：拿到二线/中厂 Unity 客户端（战斗/玩法方向）offer，用 2–3 年上线项目经验做跳板
> **核心杠杆：不是代码量，是迭代轮数 + 自己推翻自己的比率**

---

## 0. 四条铁律

1. **AI 只当 reviewer 和解释器，不当代笔。** 顺序必须是：自己写一版丑的能跑的 → 让 AI 指出问题 → 自己改。顺序反了等于没学，而且面试当场露馅。
2. **不是"学会了再投"，是"边做边投"。** 第一周就开始投保底岗。理由有两个：面试本身就是最高效的学习（你会立刻知道面试官问什么）；有收入才治得好焦虑。
3. **每个任务都要有可验收的产出。** "今天学了状态机"不算完成；"今天状态机能被攻击打断"才算完成。
4. **每次迭代留四行台账：假设 → 改动 → 观察 → 决定。** 这份台账是你最后最值钱的物料，比代码重要。

---

## 0.5 你的核心竞争力：迭代回路

"最后比拼的是想法和迭代速度"——这句话对一半，错的那一半更关键。

**想法不值钱。** 想法没有供给约束：你有，你的竞争者也有，AI 一分钟给你一百个。稀缺的从来不是想法，是**从一百个里挑出对的那个的判断力**，和**判断"这一版比上一版好"的品味**。这两样只能在真做过之后长出来。

**迭代速度也不值钱，如果每次迭代学不到东西。** 看这个分数：

```
        跑一次有多快（分子）  ← AI 已经压到接近零
迭代价值 = ─────────────────────────────────────
        每跑一次学到多少（分母）← 100% 取决于你
```

AI 把分子压到接近零。分母是你的。**分母趋近零的时候，速度再快也只是更快地走错方向**——这就是"AI 让你更快地做出错误的决定"。

所以"比想法和迭代速度"落到实处，是三个能力，全都不是"想"，全都是"做"：

1. **把一个模糊想法变成可判定的最小实验**的能力（不是"做个战斗系统"，是"验证顿帧 60ms 和 120ms 哪个手感更好"）；
2. **搭出能看见结果的观测手段**的能力（Gizmos、调试面板、Profiler、屏录回放——看不见结果就没法迭代）；
3. **在结果面前承认自己错了**的能力。这一条 AI 给不了你：**AI 倾向于宣布成功，而证伪只能自己来。**

**最关键的推论**：一个能被复制的东西没有价值。代码能被复制，AI 生成的代码能被任何人复制，你的毕设已经被 AI"复制"过了——所以它在面试里是负资产。但**"我跑了 14 轮迭代，第 3 版的顿帧方案被我自己推翻，因为……" 这句话无法被复制**，它只属于真跑过的人。这是你唯一可能的护城河类型。

## 1. 先自测：你需不需要先补 2 周基础

不看任何资料（可以查 API 文档，不许问 AI），30 分钟内完成：

> 写一个 `StateMachine`，状态有 `Enter()` / `Tick()` / `Exit()`，支持从任意状态切换到任意状态，切换时保证旧状态 `Exit` 先于新状态 `Enter`。

- **能写出来** → 直接进第 2 节。
- **写不出来** → 先在 W1 前面插 2 周：C# 值类型/引用类型、委托与事件、协程 vs async、List/Dictionary 的用法与开销、接口与抽象类。补这两周，比抄 4 周 AI 代码有用得多。

## 2. 四周冲刺

产出：**一个能跑、能录 60 秒视频、有完整迭代台账、你能讲 20 分钟的战斗原型。**

**每周迭代闭环次数下限**（这是本周的硬指标，比"写完多少功能"重要）：
W1 ≥ 3 次 ｜ W2 ≥ 5 次 ｜ W3 ≥ 10 次（打击感天然高频迭代）｜ W4 ≥ 5 次

### W1 · 状态机与角色基础
| 天 | 任务 | 验收标准 |
|---|---|---|
| D1 | 新建 URP 工程；Git + GitHub 仓库；Unity 版 .gitignore；README 骨架 | 仓库有 1 条 commit，能 clone 下来打开 |
| D2 | 自己写 PlayerController：相机相对移动、转向、重力 | 能走能跑，录一段 GIF |
| D3–D4 | 手写 `StateMachine<T>`：Enter/Tick/Exit、打断规则；输入 / 状态 / 表现三层分离 | Idle/Move/Attack/Hit/Die 能互相切，攻击中被打能打断并进入 Hit |
| D5 | 表现层接上（动画或至少位移/颜色变化） | 状态切换时表现同步，不出现"状态切了动画没切" |
| D6 | 画状态机结构图 + 本周台账整理：这周我推翻了哪个决定？ | 图 + 台账进仓库 |
| D7 | 缓冲日，补欠的债 | 闭环次数 ≥ 3 |

### W2 · 技能系统
| 天 | 任务 | 验收标准 |
|---|---|---|
| D1 | 技能数据结构：ScriptableObject（id / 前摇 / 后摇 / 伤害 / 范围 / 冷却 / 动画名） | 能在 Inspector 里配出 3 个技能资产 |
| D2 | 技能释放流程：前摇 → 判定 → 后摇 → 冷却，与状态机对接 | 技能期间不能移动/不能放别的技能（除非允许） |
| D3 | 连招：输入缓冲 + 连招窗口。**记录缓冲窗口 0.1s / 0.2s / 0.3s 的体感差异** | 攻击后摇末尾按攻击能接下一段，且台账里有窗口参数结论 |
| D4 | 三个有区分度的技能：突进斩 / 范围击飞 / 远程投射 | 三个都能打出效果 |
| D5 | 调试面板（IMGUI）：当前状态、技能 CD、当前 Buff | 运行时能看见（这是后续所有迭代的观测手段） |
| D6 | 类图 + 台账：这周哪个参数是被数据/体感否掉的？ | 进仓库 |
| D7 | 缓冲日 | 闭环次数 ≥ 5 |

### W3 · 伤害管线与打击感（迭代最密集的一周）
| 天 | 任务 | 验收标准 |
|---|---|---|
| D1 | 命中判定：OverlapBox / OverlapSphere + LayerMask + Gizmos 可视化 | 能在 Scene 里看见判定范围 |
| D2 | 伤害管线：伤害计算 → 抗性/减伤 → 事件广播 → 受击方处理（受击方不反向依赖攻击方） | 换一个敌人不用改技能代码 |
| D3 | 打击感第一轮：顿帧、硬直、击退、震屏、闪白。**逐个参数做 A/B：顿帧 40/80/120ms，震屏 0.1/0.25s……** | 台账里至少有 6 组参数对比结论 |
| D4 | Buff/Debuff：持续时间、叠加层数、周期结算、移除回调 | 能做出"中毒 5 秒每 1 秒掉血"和"攻速 +20%，持续 8 秒" |
| D5 | 数据驱动：Excel/CSV/JSON → ScriptableObject 导入工具 | 改表不用改代码 |
| D6 | 对象池：伤害飘字 / 特效 / 投射物 | 连续打 60 秒 Profiler 里没有持续增长的 GC |
| D7 | 台账整理：**这周我推翻了自己几个设计？** | 闭环次数 ≥ 10 |

### W4 · 自证（这一周决定你能不能拿到面试）
| 天 | 任务 | 验收标准 |
|---|---|---|
| D1 | Profiler 实测：帧时间与 `GC.Alloc`，做一次真的优化（去每帧 LINQ、缓存 GetComponent） | 优化前后数据对比截图进台账 |
| D2 | 60 秒演示视频（OBS 录，剪掉加载） | 能发给 HR 的链接 |
| D3 | **迭代史文档（3 页）**：架构图 + 3 个被推翻的设计 + 每个的观察依据 + 现在怎么看 | 文档进仓库。这比"技术文档"强一个量级 |
| D4 | README 重写：GIF、架构图、怎么运行、迭代了多少轮 | 陌生人能看懂 |
| D5 | 简历改写：把迭代轮数和自我证伪写进去 | 不出现"AI 辅助"，也不撒谎 |
| D6–D7 | 批量投递 + 报名一个 Game Jam | 投出 ≥15 家 |

放仓库里 `DEVLOG.md`，每行一条，不许写成日记：

## 4. 每周固定动作

- **刷题**：每天 1–2 题 LeetCode，先数组/字符串/链表/哈希/树。客户端岗也考。
- **台账**：每天四行，不许断。这是你唯一无法被复制的资产。
- **提交不断档**：GitHub 一周至少 3 次有意义的 commit。
- **Game Jam**：Global Game Jam / Ludum Dare / 国内线上 Jam，参加一次，48 小时做完一个能玩的东西。这是门槛最低、见效最快、且天然充满迭代的素材。
- **8 周后的进阶**：Addressables、UI（UGUI/UI Toolkit）、帧同步 or 状态同步原理、一个 Shader 效果、读一点引擎/框架源码。

## 5. 面试必被问的问题（提前写下你的答案）

1. 你的状态机怎么设计的？为什么不用 switch？打断规则怎么处理？
2. 为什么用 ScriptableObject 存技能数据，不用 JSON/Excel？
3. 伤害结算放在哪一层？攻击方和被击方怎么解耦？
4. 命中判定用的什么？为什么？快速移动穿过目标怎么处理？
5. 打击感你具体做了哪些事？顿帧怎么实现的，会不会影响别的东西？
6. 你这个项目最大的性能问题是什么？怎么发现的，怎么解的，优化前后数据？
7. 如果让你重做，你会改什么？
8. C#：GC 从哪来？值类型和引用类型什么时候会被装箱？
9. 协程和 async/await 的区别，分别适合什么场景？
10. LeetCode 中等题。
11. **你哪一版设计是被你自己推翻的？为什么？现在怎么看？**（这题是第 11 题，但它是分量最重的一题。答不出来，说明你只在生产，没有在迭代。）

**答不上第 1–7 和第 11 题的任何一个，就说明这个原型还没做完。**

## 6. 简历怎么写

- 不写"AI 辅助完成"，也不虚构实习。写**你负责的部分、设计决策、迭代过程**：
  > 设计并实现数据驱动的战斗系统：以状态机管理角色行为与技能打断，以 ScriptableObject 承载技能配置，抽象伤害结算管线解耦攻防双方；通过对象池与 Profiler 实测将战斗过程 GC 分配降至 0。整个原型经历 14 轮迭代，其中 3 处设计（顿帧策略、技能数据载体、连招缓冲窗口）被实测结果推翻并重构。
- **最后那句是整份简历里最值钱的一句**，因为它是 AI 生成不出来的，也是从你代码里复制不走的。
- 结构：1 个深挖的主项目 + 1–2 个小原型（Jam 作品）。宁少勿虚。
- 驾照、毕业证不用写。没有实习就用项目密度和迭代密度补。
- 毕设工程如果找不到或跑不起来，不要硬包装，直接用新原型替代。
